# Catalogue Page Documentation

## Purpose
The catalogue page is a marketing-to-configurator listing that presents product cards in a masonry-style grid, highlights product visuals, and links visitors to product configurators or product pages.

## Entry point
- File: `catalogue.html`
- Global scripts: `js/main.js` (site-wide behavior)
- Icons/Fonts: Phosphor icons via CDN, Google fonts
- Styles: `css/style.css` plus page-specific inline CSS for the catalogue layout

## Page anatomy

- Header: shared site header with navigation and active `Catalogue` link.
- Hero: large hero section (`.hero`) with title, subtitle, CTA (`Configurator`), and hero imagery.
- Main catalogue grid: `.catalogue-container` -> `.catalogue-grid` using CSS `column-count` for masonry effect.
- Product card link (`.product-card-link`) wraps each `article.product-card` to make the whole card clickable.
- Product card parts:
  - `.product-image-area` — image container with variant heights (`.h-small`, `.h-large`) and `img` with `object-fit: cover`.
  - `.gallery-like` — wishlist/like button (handled in `js/main.js`).
  - `.product-content` — contains `.product-name`, `.product-dims`, and other meta like `.product-customization`.
- Footer: site footer and `js/main.js` script included at the end of the page.

## Visual & layout notes
- Masonry is implemented via CSS `column-count: 4` with `break-inside: avoid` on card wrappers.
- Card hover visual effects use pseudo-elements (`::before`, `::after`) for frame overlays and orange CTA overlay.
- Card sizes alternate via `.card-small` and `.card-large` classes for a staggered layout.
- Responsive breakpoints switch column counts and adjust paddings at 1200px, 900px, and 640px.

## Interactions
- Card click: the entire `.product-card-link` anchors to `product-page.html` (or another product entry).
- Wishlist like button: `.gallery-like` toggles via `js/main.js` (adds/removes `ph-fill` classes and swaps colors).
- Smooth scrolling: anchor links are handled globally by `js/main.js`.
- Hero CTA: scrolls to `#catalogue` anchor (internal link behavior handled by `main.js`).

## Data and assets
- Product images live in `assets/` (e.g., `assets/cabinet.jpg`, `assets/wood_oak.png`).
- Product metadata (name, dimensions) is currently hardcoded in the HTML.

## Accessibility and SEO
- Each card is a link with an `alt` attribute on images — ensure alt text describes the product.
- Wishlist buttons use `aria-label` but could benefit from `aria-pressed` and keyboard focus styles.
- Consider using semantic product microdata (schema.org/Product) for SEO if integrating product data dynamically later.

## Implementation notes
- `catalogue.html` contains inline CSS that overrides some global tokens for layout specifics (hero height, container width).
- Keep card markup consistent (link -> article -> image area + content) so `js/main.js` can reliably attach behaviors.
- If converting to dynamic data in future, replace repeated card markup with a templating approach and inject product metadata from JSON.

## Maintenance recommendations
- Move page-specific CSS into `css/style.css` or a separate `css/catalogue.css` to reduce inline styles.
- Replace hardcoded product cards with a single template and a JSON data source when product data grows.
- Add `aria-pressed` to `.gallery-like` and ensure keyboard toggles work.
- Consider lazy-loading images with `loading="lazy"` for performance improvements.
