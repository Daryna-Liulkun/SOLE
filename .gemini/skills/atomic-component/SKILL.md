# Atomic Component — Component-Driven Architecture

Ти будуєш або редагуєш конкретний компонент у дизайн-системі. Твоя мета — повна ізоляція компонентів та 100% відповідність токенам.

## ЗОЛОТІ ПРАВИЛА
- **Storybook-First (SDD):** Будь-яка зміна спочатку реалізується та перевіряється у візуальному середовищі `[Name].stories.jsx`.
- **Аналіз Залежностей (Bottom-Up):** Якщо просять змінити Організм, СПОЧАТКУ перевір, чи це не властивість вкладеного Атому. Якщо так — змінюй Атом.
- **Prop Propagation:** Якщо атомові потрібен новий стан, прокидай його через пропси зверху вниз. Жодного хардкоду стилів атому всередині організму.
- **Import Contract:** SVG та іконки — це атоми. Вони мають бути JS-константами (export const chevronIcon = \`...\`) і використовуватись через `import`. Inline SVG рядок у будь-якому файлі за межами самого атому — це порушення, не стилістичний вибір.

## АНАТОМІЯ ПАПКИ КОМПОНЕНТА (Mandatory)
Кожен компонент створюється як окрема папка `design-system/[level]/[Name]/`. Вона МАЄ містити:
- `[Name].jsx` — логіка компонента, використання пропсів.
- `[Name].css` — ТІЛЬКИ CSS змінні (var(--token)). Жодних 16px чи #FFF.
- `[Name].stories.jsx` — Storybook документація для кожного варіанту, розміру та стану (default, hover, disabled).
- `README.md` — Контракт компонента (таблиця пропсів, опис поведінки, залежності).

## ПЕРЕКЛАДАЧ ЛЮДСЬКОЇ МОВИ (Semantic Mapping)
Якщо користувач формулює запит "по-людськи":
- "Зроби більшим/меншим": Знайди поточний токен (напр. --text-md), відкрий TOKENS.md і використай наступний крок шкали (--text-lg).
- "Додай повітря": Перейди на більший --space-*.
- "Зроби [колір]": Знайди в TOKENS.md семантичний колір (напр. --color-primary). ЗАВЖДИ запитуй: "Зробити це глобально (змінити сам токен) чи локально (створити новий Variant компонента)?"

## Режим: create [level] [Name]
1. Прочитай `TOKENS.md` та `COMPONENTS.md`. Перевір, чи не існує вже такого компонента.
2. Запитай деталі: variants, sizes, states.
3. Створи папку з усіма 4 файлами.
4. **Авто-Реєстрація:**
   - В `design-system/index.js` додай: `export * from './[level]/[Name]/[Name]';`
   - В `design-system/index.css` додай: `@import "./[level]/[Name]/[Name].css";`
5. Онови `COMPONENTS.md`.

## Режим: edit [level] [Name]
1. Прочитай всі 4 файли компонента та його `README.md`.
2. Якщо це Молекула/Організм — переглянь README вкладених атомів.
3. **Grep для inline дублікатів (ОБОВ'ЯЗКОВО перед змінами):** Знайди ключовий рядок атому що змінюється (SVG path, унікальний клас). Виконай grep по `design-system/` щоб знайти файли що містять цей рядок не через import — це приховані залежні, їх треба оновити в тому ж проході.
   - `COMPONENTS.md` описує архітектуру. `grep` описує реальність. Обидва — обов'язкові.
4. Внеси зміни спочатку в `stories.jsx`, потім в `jsx/css`.
5. Онови контракт у `README.md`.

## Режим: check [level] [Name]
Перевір компонент: наявність всіх 4 файлів, відсутність хардкодів у CSS, покриття сторіями всіх станів, aria-атрибути, відсутність inline SVG дублікатів у файлах-споживачах (grep). Виведи звіт.
